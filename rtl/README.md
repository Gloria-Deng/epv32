# `rtl/` 目录说明

这里是本设计全部可综合的 Verilog 源码：RV32IM + Zicsr 五级流水核、它的 EPV 自定义向量单元、片上外设与 SoC 顶层。**本目录是唯一真源**——`results/` 各臂目录里同名的那些 `.v` 是综合器当时实际吃进去的输入快照（分工见 `results/README.md`），`build/sim*/` 下的 C++ 是 Verilator 由这里生成的；两类都不是第二份源码，也不许「顺手同步」。另有一层单一出处关系值得先说清：指令编码与地址图只定义在 `epv32_defs.vh` 一处，黄金模型 `tb/golden/epv_iss.py` 与软件头 `sw/inc/epv32_hw.h` 是它的抄本。

| 文件 | 职责 | 谁产出 | 可否手改 | 报告落点 |
|---|---|---|---|---|
| `epv32_defs.vh` | 指令编码与地址图的唯一真源：标准主操作码、EPV 的 funct3/funct7 表（扩展指令条数由 `EPV_N_INSTR` 给出）、SoC 各段基址与寄存器偏移、异常因果与中断编码 | 人写 | 可以，但改完必须跑 `python tools/check_encoding_consistency.py`——它逐条比对 RTL 表、汇编出的机器码与黄金模型这几处抄本，任一处不一致即判红 | 报告 3.3、3.4；附件 A.14 |
| `epv32_core.v` | 五级流水（IF/ID/EX/MEM/WB）核本体，含冒险与陷入汇聚、乘除与 EPV 的分派。头注释按 M1~M6 逐条写着刻意的微架构决定，以及每条各自的代价 | 人写 | 可以；它是面积/周期读数的来源，改完要让 `python flow/run_all.py` 的测量步重跑一遍 | 报告 3.2；附件 A.14 |
| `epv32_epv.v` | EPV 向量运算单元：多周期搬运状态机借核的数据总线做整字进出，点积/重量化/逐 lane 运算按 generate 展开；整条生命周期待在 EX 级，因此不需要向量前递网络 | 人写 | 可以；语义改动要与 `tb/golden/epv_iss.py`、`sw/inc/epv32_hw.h` 同步（同上那条编码门） | 报告 3.3；附件 A.14 |
| `epv32_alu.v` | 整数 ALU 与比较（含 `ALU_PASS` 直通，供 LUI 与 CSR 读复用）。分支与 `slt` 只取这里的比较位，不留第二处真源 | 人写 | 可以 | 报告 3.2；附件 A.14 |
| `epv32_rf.v` | 通用寄存器堆，x0 恒零，读端口带 WB 同级写穿 bypass | 人写 | 可以 | 附件 A.14 |
| `epv32_muldiv.v` | RV32M 乘除单元：乘法单拍、除法按位循环；操作数在启动那一拍打快照（核会把本条指令冻在 EX，直接吃输入端口会读到陈旧值） | 人写 | 可以 | 报告 3.2（M2）；附件 A.14 |
| `epv32_csr.v` | 机器模式 CSR、PMP 与周期/退休计数器，以及中断判定。未定义 CSR 的读回行为、MPP 恒为 M 模式这类边界是在这里定的 | 人写 | 可以；改 CSR 或 PMP 语义要连带看 `sw/bench/micro_bisect.c` 那组逐项探针 | 报告 3.5、5.2；附件 A.4 |
| `epv32_ram.v` | 主存行为模型（取指口 + 数据口，异步读、带字节使能的同步写）。核的总线协议「恒 1 周期就绪」据此成立 | 人写 | 可以 | 报告 3.4；附件 A.11 |
| `epv32_soc.v` | 同一份文件里装着外设与顶层：可上板的 8N1 UART、机器计时器、平台控制与提交口、地址译码，以及交付仿真顶层 `epv32_soc` | 人写 | 可以 | 报告 3.4、3.8；附件 A.17 |
| `synth_wrappers.v` | 综合用的薄顶层封装：把 `EPV_ENABLE` 分别钉成开与关，使两档面积对照没有歧义；所有核输出折进 `probe` 端口，好让「统计为空」没法伪装成成功 | `tools/make_wrappers.py` 生成（文件头那行 `Generated by tools/make_wrappers.py -- DO NOT EDIT BY HAND.` 就是它的来历） | **不可手改**——手改会在下一次运行生成器时被整份覆掉；要动顶层形状就动生成器 | 报告 3.6；附件 A.14、A.23 |
| `epv32_assert_core.vh` | 核的结构不变式（流水冻结、重定向排除期等），前仿期间开火而不是停在注释里；失败打 `EPVASSERT FAIL <tag>`，装载成功由 `EPVASSERT CORE_ARMED` 自证 | 人写 | 可以；但每加一条检查就要在 `flow/assert_selfcheck.py` 的注入臂里给它一条反例——一条从不开火的断言与一条不存在的断言在报告里长得一样。条数见 `results/asserts/mutation_proof.json` | 报告未单列这一层；判据与读数在 `flow/assert_selfcheck.py` 与 `results/asserts/mutation_proof.json` |
| `epv32_assert_epv.vh` | 向量单元的同类不变式，挡的是「搬运还在跑时向量寄存器堆被半截结果写脏」这一类延迟显形的失效 | 人写 | 可以；同上，新增检查要配注入反例 | 同上 |

断言那些 `.vh` 不进综合口径，这一点是可以自己核的：`epv32_core.v` 与 `epv32_epv.v` 里各自那句 `` `ifdef EPV_ASSERTIONS `` 是它们唯一的装载门；`flow/synth_core_epv.ys`、`flow/synth_core_noepv.ys`、`flow/synth_epv.ys` 那几个脚本按文件名逐个列出输入、从不提断言文件，`bash flow/lint_rtl.sh` 也不定义那个宏。只有 `bash flow/build_sim.sh` 的 `ASSERT=1` 那一臂带 `+define+EPV_ASSERTIONS`，并且它落在另一个目录、另一个可执行名上，不覆写认证仿真器。所以面积与周期读数与该层无关。

读 `epv32_epv.v` 时会看到端口 `i_gpr2`：它在核侧由前递结果 `fwd2` 驱动，但单元内部不消费它，只被 `wire _unused_ok = &{1'b0, i_gpr2, 1'b0};` 吃掉以免 lint 报未使用信号。文件里那段注释把它定性为「已证明惰性的预留接口」并写明了保留理由，这是刻意的形状，不是漏连的 bug——别顺手去「修」它，删它要动核侧连线而没有任何收益。

## 读这个目录的正确顺序

1. `epv32_defs.vh` —— 先拿到编码表与地址图，后面每一份文件都在引用它。
2. `epv32_core.v` 的头注释（M1~M6）—— 那些微架构决定和它们各自的代价，是全目录的骨架。
3. `epv32_epv.v` 的头注释 —— 数据通路与「只在 EX 读、完成拍写」的流水线约定。
4. 叶级模块 `epv32_alu.v`、`epv32_rf.v`、`epv32_muldiv.v`，再看 `epv32_csr.v`（这份的边界最多）。
5. `epv32_soc.v` 与 `epv32_ram.v` —— 从这里开始才是仿真顶层。
6. 只有在读**面积数字**的时候才需要看 `synth_wrappers.v`，它不影响任何行为语义。
7. 最后是 `epv32_assert_*.vh` —— 它们只在断言臂里存在，先读会误以为是流水逻辑的一部分。

想动手验证哪一层都在跑：最快的入口依次是 `bash flow/lint_rtl.sh`（只查语法与两档 elaboration）、`bash flow/build_sim.sh`（造仿真器）、`python flow/rt.py bench sw/bench/epv_selftest.c --max-cyc 400000`（跑一个用例并落归档）。

## 不在这个目录里／容易误以为在这里

- **同名副本不是源码。** `results/pnr/*/rtl/` 下面确实有 `epv32_core.v` 这些名字，那是那一臂综合时逐字节拷进去的输入快照，用来证明「这一趟吃进去的是什么」。改这里不会改到行为，反过来也一样。
- **生成物在别处。** `build/sim/`、`build/sim_assert/`、`build/sim_cov/` 里的 C++ 与可执行文件由 `flow/build_sim.sh` 生成；`results/synth/`、`results/pnr/` 里的统计表由 `tools/synth_archive.py`、`tools/pnr_archive.py` 汇综。本目录不含任何脚本或产物。
- **模型与台架不在这里。** Verilator 测试台是 `tb/sim_main.cpp`，黄金指令集模型是 `tb/golden/epv_iss.py`，软件侧的编码镜像是 `sw/inc/epv32_hw.h`。它们与 `epv32_defs.vh` 的一致性是一条门禁（`tools/check_encoding_consistency.py`），不是人工约定。
- **没有 SystemVerilog / UVM，也没有额外的功能顶层。** 源码只有 `.v` 与 `.vh` 两种后缀（这份说明不是源码）；`epv32_soc` 是交付的仿真顶层，`synth_wrappers.v` 里的顶层只是面积档封装。
- **`synth_wrappers.v` 不在仿真新鲜度的账上。** `flow/run_all.py` 构建仿真器那一步把它排除在源文件集合之外（它只被综合脚本读），所以改它不会让仿真归档判过期；反过来说，「这份文件动了」也不构成一次微架构改动。
